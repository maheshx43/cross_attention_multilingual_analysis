# Implementation notes for released Python exports

These notes document implementation details discoverable in the released source and saved protocol files. They are intended to make the Python-only release easier to audit without changing the scientific routines.

## Language identification

The fp32 generation collectors use `cis-lmu/glotlid`, file `model_v3.bin`, pinned at revision `85cd6716494360367b75f642b5bc78667605d0b4`. The model is loaded through `huggingface_hub` and `fasttext`. Non-empty hypotheses are scored with `k=1`; the returned label has the `__label__` prefix removed and the returned probability is deposited as `lid_probability`. Empty hypotheses receive the label `EMPTY` and probability `0.0` in the E6 path. `off_target` is the exact comparison `lid_label != target` (or `lid_label != tag` in the intervention collector). No additional probability threshold is applied. Existing predictions are retained and indexed; they are not regenerated by the release validator.

## E6/E7 support and undefined attention

E6 retains all behavioral output rows for diagnostics. Attention rows with no lexical attention query or otherwise undefined attention are not zero-filled. The common complete-meaning set is formed by intersecting the eligible whole-meaning supports across the three systems, and E6/E7 retain 444 meanings with the original partition filtered to 309 train / 67 validation / 68 test. The primary attention support is 444 × 40 = 17,760 rows per system and regime, with 68 test meanings.

## Separator and conditional-mass outcomes

The released E4/E6 collectors expose `conditional_no_separator` and related fields in their saved outputs. These are distinct from the raw lexical-mass outcome. The source records blank/separator counts and masses, and the conditional statistic is explicitly labeled as excluding blank separator pieces. The exact tokenizer-specific position masks and source labels remain in the collector exports and their saved source/provenance files; the release does not infer missing values or silently convert undefined conditional denominators to zero.

## E2 likelihood protocol

The saved E2 protocol identifies the confidence feature as `retokenized-saved-hypothesis-content-logprob-v2`. It is a verified content likelihood of retokenized saved hypotheses and is explicitly not the exact original sampling-path token likelihood. The protocol records training-directed-mean source-plus-target calibration, five-fold meaning-crossfitted training residuals, training-only confidence imputation with missingness flags, and strict meaning/dyad holdout. The primary comparison is `I_controlled_likelihood_signed_residual` versus `G_controlled_likelihood` on held-out COMET Spearman correlation. See `results/validation/E2_quality_comet_v1/protocol.json`, `analysis_settings.json`, and the E2 exported source for the complete feature construction.

## Model-specific statistical coverage

The IT2/NLLB historical field analyses include the exact-gradient or related sampling-null procedures described by their source scripts. MADLAD’s added E3/E4 evidence includes fp32 gradient-energy and permutation/sensitivity analyses, but it should not be interpreted as having the same historical exact-gradient noise test unless a source/result manifest explicitly says so. The release validator checks provenance and support metadata; it does not claim that different model analyses used identical null procedures.

## Validation limits

`python3 scripts/validate_release.py` checks file existence, split sizes, E6/E7 support counts, manifest paths, and listed SHA-256 entries. It does not rerun model inference, language identification, COMET scoring, attention collection, bootstraps, tensor-level tests, or regression fits.
